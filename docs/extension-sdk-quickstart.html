BuildSuite extension SDK

From zero to a customised BuildSuite in four steps

An extension is an ordinary Frappe app with one extra line and a small JavaScript file. It adds pages, tiles and sections to BuildSuite Core without rebuilding Core, and uninstalling it removes them again.

Step 1

Scaffold the app

Step 2

Declare it and customise

Built: hook, page, slot, tile, view override, form hooks, settings page, field rules, list columns and presets
hooks.py (the only BuildSuite line)
buildsuite_frontend_extensions = [{
  "name": "acme_ext",
  "js":   "/assets/acme_ext/js/extension.js",
  "min_sdk": "1.6",
}]

# a settings page with no JavaScript: a Single DocType
buildsuite_settings_pages = [{
  "doctype": "Acme Settings",
  "group": "Acme", "label": "Acme settings",
}]

Frappe lists the hooks of installed apps only, so the extension is active exactly where the app is installed. The Custom Fields it adds are ordinary Frappe fixtures.

public/js/extension.js
export default function register(sdk) {
  // a new page inside the app shell
  sdk.routes.add({ path: "site-diary", component: SiteDiary });

  // a tile on the Sales workspace
  sdk.workspaces.addTile("sales", {
    label: "Site diary", to: "/site-diary",
  });

  // a component above or below ANY page, bespoke or not
  sdk.slots.add("page.app-home.top", Banner);

  // a control for a Custom Field on a bespoke form (all 20 create forms)
  sdk.doctype("Quotation").on({ fields: ["region"] });
  sdk.slots.add("form.Quotation.top", RegionControl);
  sdk.slots.add("form.Quotation.after.field.title", Hint);  // beside one field

  // change how a Core field behaves; a rule can follow the other fields
  sdk.doctype("Quotation").on({
    fieldRules: {
      margin_percent: { hidden: true },
      region: (ctx) => ({ required: ctx.form.project_type === "Commercial" }),
    },
    beforeSave(payload) {
      // a message under one field, and the save stops
      throw new sdk.FieldErrors({ region: "Pick a region" });
    },
  });

  // replace a Core page, or render around it
  sdk.views.override("settings-app-icon-diagnostics", MyDiagnostics);
  sdk.views.wrap("settings-data", MyFrame);

  // hooks on the generic DocType form ("*" = every doctype)
  sdk.doctype("*").on({ beforeSave(payload) { /* throw to refuse */ } });

  // a column (also a sort option) and a one-click preset on a Core list
  sdk.doctype("Project").on({
    listColumns: [{ field: "custom_region", label: "Region" }],
    listFilters: [{ label: "North only", filters: [["custom_region", "=", "North"]] }],
  });
}
Step 3

Load it

Built: loading at runtime; optional build kit for .vue files
Terminal
# extension.js is plain JavaScript: Vue arrives as sdk.vue
bench --site mysite migrate   # only if you ship fixtures or doctypes

Reload the app. Core loads extension.js at runtime from the installed app, checks the SDK version, and calls register(sdk). An extension that fails to load or throws while rendering is logged and skipped, and the page around it keeps working.

Core's own bundle is never rebuilt, and Core's build never depends on which apps are on the bench. Writing components as .vue files? The build kit (frontend/sdk-kit/vite.mjs) bundles them against Core's own copies of Vue and the controls.

Later

No code at all

Built: first slice Planned: editor and AI

A site administrator can already customise a site as data, with no app: a BuildSuite Customisation record adds a list column, a form field (a Custom Field's control), a workspace tile or a notice, and takes effect on the next page load. Core validates every record strictly and applies it after the installed apps, so the site's own choice wins. The editor or onboarding page that writes these records, an AI that authors them, and drag-and-drop are parked for the AI-authoring work.

Where the SDK lives: inside Core

buildsuite_core.sdk

The Python half: extension discovery, settings pages, seed_if_missing, Custom Field helpers for bespoke save APIs, the customisation validators and the scaffold.

register(sdk)

The JavaScript half is the object an extension receives: routes, slots, views, doctype hooks, field rules, list extras, plus Core's own Vue and controls.

bench new-buildsuite-extension

Writes the starter app. There is no template repo and there are no separate SDK packages: an extension runs on a site that has BuildSuite Core installed.

One version covers both halves (SDK_VERSION, now 1.6); an extension states the minimum it needs with min_sdk.
